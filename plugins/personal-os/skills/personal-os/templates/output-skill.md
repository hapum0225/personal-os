# 형태 A · Claude 스킬 만들기 (output-skill)

첫 부품을 **Claude 스킬**로 만든다. 가장 가볍고, 인터뷰가 끝나는 순간 바로 쓸 수 있다. Step 6에서 이 템플릿으로 분기했다면 아래 질문(Q 톤)을 따른다.

## 언제 A인가
글·문서를 인터뷰·정리·생성하는 도우미, Claude 안에서 발동되는 워크플로우. (터미널 자동 실행·훅이 필요하면 → B, Claude를 안 쓰는 사람도 써야 하면 → C.)

## Step 6 질문 (Q 톤 — 발판 제공)

한 번에 하나씩 묻되, 막히면 발판 예시를 준다.

1. **한 줄 정체성** — "이 스킬을 한 문장으로 하면? 예: '매주 콘텐츠 성과를 회고하고 다음 주 주제를 뽑아주는 도우미'."
2. **트리거** — "어떤 말/상황에서 발동돼야 하나요? 3~5개. 한국어와 영어를 섞어도 좋아요. 예: '이번 주 회고', 'weekly review'."
3. **발동하면 안 되는 상황** — "헷갈려서 잘못 튀어나오면 곤란한 상황이 있나요? 예: 단순 일정 확인."
4. **인터뷰/작동 단계** — "이 스킬이 몇 단계로 움직이면 좋을까요(3~6)? 각 단계에서 핵심적으로 물어볼/할 일 하나씩."
5. **최종 출력** — "끝나면 뭐가 남아야 하나요? 예: `weekly-review-<날짜>.md` 한 파일."

## 만들기 전 · 참고 사례 논의 + 유형

- 결과물을 만들기 전에 [`../references/reference-borrowing.md`](../references/reference-borrowing.md)에 따라 **"참고 사례를 찾아볼까요?"를 먼저 묻는다**(물어본 뒤 검색·토큰 상한·출처 기록).
- 이 부품의 **유형**([`../references/os-types.md`](../references/os-types.md): 개인 / 삶 / 업무 › 세부)을 확인하고, 결과물 상단에 배지로 남긴다.

## 산출물 골격 (단일 출처)

`<output_dir>/<skill-slug>/SKILL.md`로 만든다. **평면 `<이름>.skill.md` 파일이 아니라 폴더 안 `SKILL.md`**여야 한다(최신 개인 스킬 규격).

```markdown
---
name: <skill-slug>
description: <무엇을 하는지 + 언제 발동하는지. 3인칭. 한국어/영어 트리거 포함. 발동 제외도 한 줄.>
---

# <스킬 이름>

<한 줄 정체성>

> 유형: <개인 / 삶 / 업무 › 세부카테고리>

## 언제 이 스킬을 쓰는가
- 발동: <트리거 상황·키워드>
- 발동하지 않음: <제외 상황>

## 작동 방식
### 1단계 · <이름>
- 핵심 질문/동작: ...
### 2단계 · <이름>
- ...
<3~6단계>

## 출력
<끝나면 남는 것: 파일 이름·형식>
```

## 파일 안전 규칙
- 이름은 `..`·경로 구분자·예약문자를 제거하고 **kebab-case slug**로 정규화한다.
- 승인된 출력 폴더 밖에 쓰지 않는다.
- 같은 이름의 폴더·파일이 있으면 덮어쓰지 말고 `-v2`를 붙인다.
- Write가 불가하면 채팅 코드블록으로 폴백한다.

## 완료 조건 (검증 통과 후에만 "완료")
1. 만든 `SKILL.md`를 **다시 읽는다.**
2. frontmatter의 `name`이 kebab-case이고, `description`에 무엇+언제가 들어 있는지 확인.
3. 폴더 구조가 `<skill-slug>/SKILL.md`인지 확인(평면 파일 아님).
4. 하나라도 어긋나면 고쳐서 다시 검증한다.

## 콜드리더 자립성 점검
산출물이 **설명 없이도** 제대로 발동·사용될지 확인한다. 서브에이전트를 쓸 수 있으면 이 `SKILL.md`만 새 관점에 주고 "이 스킬 언제 발동돼? 뭘 하면 돼?"를 물어 맞는지 본다. 못 쓰면 스스로 체크리스트로 점검하고, 약식 점검임을 사용자에게 밝힌다.

## 설치 제안 (외부 위치 변경 — 명시적 승인 필요)
검증을 통과하면 제안한다: "지금 바로 스킬 폴더에 설치해 드릴까요?"

- 대상: macOS/Linux `~/.claude/skills/<skill-slug>/`, Windows `$env:USERPROFILE\.claude\skills\<skill-slug>\`.
- 같은 이름의 스킬이 이미 있으면 **자동 교체하지 않는다.** 비교 요약과 백업 위치(`<skill-slug>.bak-<날짜>`)를 먼저 제시하고 승인받는다.
- 설치 후 현재 세션에 반영하려면 새 세션을 시작하거나 스킬을 다시 불러야 함을 알린다.
