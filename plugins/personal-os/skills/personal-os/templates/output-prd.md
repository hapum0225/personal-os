# 형태 C · 독립 프로덕트 PRD 만들기 (output-prd)

첫 부품을 **Claude 밖에서도 도는 독립 제품**(웹·앱·CLI)으로 만들 준비를 한다. 산출물은 PRD 한 파일이고, 이걸 Claude Code에 던져 구현으로 이어간다. 셋 중 가장 상세하다.

## 언제 C인가
Claude를 안 쓰는 사람도 써야 하거나, 모바일에서 돌아야 하거나, 공유 가능한 URL이 필요할 때.

## Step 6 질문 (Q 톤 — 발판 제공)

1. **한 줄 정체성** — "이 제품을 한 문장으로? 예: '프리랜서가 청구서를 3분 만에 만드는 웹앱'."
2. **타겟 페르소나** — "누가 쓰나요? 가장 대표적인 한 명을 구체적으로."
3. **핵심 기능 3~5개** — "이게 없으면 제품이 아니다 싶은 기능만."
4. **MVP 스코프** — "당신이 이 일에 낼 수 있는 시간이 얼마쯤인가요? 그 안에 넣을 최소 기능은?" (원본의 '1주 고정' 대신 사용자 가용 시간 기준으로.)
5. **기술 스택** — "선호하는 언어·프레임워크가 있나요? 없으면 추천받으실래요?"
6. **인증 & 저장** — "로그인이 필요한가요? 데이터는 어디에 저장되나요?"
7. **첫 검증 방법** — "만들면 누구에게 어떻게 보여주고 '되는지'를 확인할 건가요?"
8. **확장 방향** — "MVP 다음에 붙일 것 1~2개."

## 만들기 전 · 참고 사례 논의 + 유형

- 결과물을 만들기 전에 [`../references/reference-borrowing.md`](../references/reference-borrowing.md)에 따라 **"참고 사례(비슷한 제품)를 찾아볼까요?"를 먼저 묻는다**(물어본 뒤 검색·토큰 상한·출처 기록).
- 이 제품의 **유형**([`../references/os-types.md`](../references/os-types.md): 개인 / 삶 / 업무 › 세부)을 확인하고, PRD 상단에 배지로 남긴다.

## 산출물 골격 (단일 출처)

`<output_dir>/<product-slug>.prd.md` 한 파일로 만든다.

```markdown
# <제품 이름> — PRD

> 유형: <개인 / 삶 / 업무 › 세부카테고리>

## Why (배경)
<이 제품이 푸는 반복 소모 — Step 2~3에서>

## Who (타겟)
<대표 페르소나 한 명>

## What (핵심 기능)
1. ...
2. ...

## MVP Scope (가용 시간 기준)
<이번에 만들 최소 기능 + 수용 기준(acceptance criteria)>

## 비기능 요구
<성능·접근성·보안 등 최소 요구>

## Tech Stack
<언어·프레임워크·주요 라이브러리>

## Auth & Storage
<인증 방식 · 데이터 저장 위치>

## Validation Plan
<누구에게 어떻게 보여주고 성공을 판정할지>

## Future (다음)
<MVP 이후 확장 1~2개>

## 미결정 사항
<아직 정하지 못한 것들 — 구현 전에 답이 필요한 질문>

---

## Claude Code 구현 프롬프트
새 폴더에서 Claude Code를 켜고 아래를 던진다:
> "이 PRD로 MVP를 구현해줘. MVP Scope와 수용 기준부터 시작하고, 미결정 사항은 먼저 물어봐줘."
```

## 파일 안전 규칙
slug 정규화 / 출력 폴더 밖 금지 / 동명 파일 `-v2` / Write 불가 시 코드블록 폴백.

## 완료 조건 (검증 통과 후에만 "완료")
1. 만든 `.prd.md`를 다시 읽는다.
2. **요구사항·비기능 요구·수용 기준·미결정 사항**이 모두 들어 있는지 확인한다(하나라도 비면 미완).
3. 어긋나면 고쳐서 재검증한다.
