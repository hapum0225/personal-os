# 1인 강사의 OS 청사진

- **작성일**: 2026-07-24
- **유형**: 개인 (본인 수강생 명단·커리큘럼에 종속)
- **OS Core**: 수강생 이름과 이번 주 진도만 넣으면, 그 사람 맞춤 피드백 초안이 나오는 구조.

## 1. 생활 환경 (지금)
온라인 강의를 혼자 운영. 시간을 가장 많이 쓰는 활동: (1) 강의 제작, (2) 수강생 피드백, (3) 문의 응대.

## 2. 반복 소모 (반복 비용)
수강생 20여 명에게 매주 진도 맞춤 피드백을 한 명씩 처음부터 작성. 비용 유형: **집중력 + 정리 비용**. 스위치 스토리로 "한 명당 지난 제출물·기록을 다시 뒤져보는 10분 × 20명"이 드러남.

## 3. OS Core (이게 풀리면)
수강생 이름과 이번 주 진도만 넣으면, 지난 기록을 다시 안 뒤져도 그 사람 톤에 맞는 피드백 초안이 떠서 다듬기만 하면 되는 상태. → 한 문장: *수강생 이름과 진도만 넣으면 맞춤 피드백 초안이 나오는 구조.*

## 4. 부품 지도 (도달 경로)
- [ ] 수강생별 지난 기록을 한곳에 모으는 것 *(입력 처리)*
- [x] **수강생 맞춤 피드백 초안기** ← **첫 부품 (이번에 만든 것)** *(출력 생성)*
- [ ] 공통 질문 자동 답변(FAQ) *(결정 보조)*

가장 비어 있는 묶음: 출력 생성.

## 5. 첫 부품
- **이름**: `student-feedback-drafter`
- **유형**: 개인
- **형태**: A (스킬)
- **결과물**: `student-feedback-drafter/SKILL.md`

## 6. 다음 부품 후보 (다음 인터뷰에서)
- 수강생별 지난 기록 자동 수집(입력 처리) — 이게 되면 피드백기에 진도를 직접 안 넣어도 됨.

## 결정 로그
- OS Core를 '수강생 이름·진도 → 맞춤 피드백 초안'으로 잡음 — 이유: 매주 20명 피드백이 가장 큰 반복 소모라서.
- 유형을 '개인'으로 봄 — 이유: 내 수강생 명단·커리큘럼·말투에 묶여 다른 강사가 그대로 못 씀.
- 첫 부품으로 '피드백 초안기'를 고름 — 이유: 주당 회수 시간이 가장 크고, 품질도 바로 올라감.
- 형태를 A(스킬)로 정함 — 이유: 정보를 물어 글을 생성하는 대화형이라 가장 가볍고 즉시 사용 가능.
- 참고 차용: 참고 없이 처음부터 (피드백 톤이 내 강의에 특화되어 참고 사례가 오히려 방해).
