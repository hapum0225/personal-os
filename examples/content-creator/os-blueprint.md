# 콘텐츠 크리에이터의 OS 청사진

- **작성일**: 2026-07-24
- **OS 선언문**: 나는 이번 주에 뭘 만들지 고르기만 하고, 성과 집계와 주제 추천은 시스템이 한다.

## 1. 풍경 (지금)
주 3회 영상을 올리는 1인 크리에이터. 시간을 가장 많이 쓰는 활동: (1) 편집, (2) 주제 기획, (3) 성과 확인·정리.

## 2. 통점 (반복 비용)
매주 일요일 밤, 여러 플랫폼에 흩어진 성과 데이터를 손으로 모아 스프레드시트에 옮기고 다음 주 주제를 고른다. 비용 유형: **정리·전달 비용**이 가장 큼(가설 검증에서 확인). 스위치 스토리로 "숫자를 옮겨 적는 30분 + 주제 고르며 멍때리는 30분"이 드러남.

## 3. 이상향 (이게 풀리면)
일요일 밤 책상에 앉으면 지난 주 성과 요약이 이미 정리돼 있고, 다음 주 주제 후보 3개가 떠 있어 고르기만 하면 되는 상태.

## 4. 부품 후보 (도달 경로)
- [ ] 플랫폼별 성과를 한곳에 모으는 것 *(입력 처리)*
- [x] **주간 회고 + 주제 추천 도우미** ← **첫 부품 (이번에 만든 것)** *(결정 보조)*
- [ ] 확정 주제를 촬영 체크리스트로 펼치는 것 *(출력 생성)*

가장 비어 있는 묶음: 결정 보조.

## 5. 첫 부품
- **이름**: `weekly-content-review`
- **형태**: A (스킬)
- **결과물**: `weekly-content-review/SKILL.md`

## 6. 다음 부품 후보 (다음 인터뷰에서)
- 플랫폼별 성과 자동 수집(입력 처리) — 이게 되면 회고 도우미에 숫자를 직접 안 넣어도 됨.

## 결정 로그
- 첫 부품으로 '주간 회고 + 주제 추천'을 고름 — 이유: 일요일 밤 1시간을 직접 돌려줌(주당 회수 시간 최대).
- 성과 자동 수집(입력 처리)을 뒤로 미룸 — 이유: 외부 API 연동이라 무겁고, 회고 도우미만으로도 절반은 해결됨.
- 형태를 A(스킬)로 정함 — 이유: 데이터를 물어 정리·추천하는 대화형이라 스킬이 가장 가볍고 즉시 사용 가능.
