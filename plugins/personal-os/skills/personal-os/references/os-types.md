# OS 유형 분류 (os-types)

첫 부품(그리고 그 사람의 OS)이 어떤 성격인지 **유형 배지**로 표기한다. Step 5에서 Claude가 근거와 함께 제안하고 **사용자가 확인**한 뒤, 청사진 헤더와 결과물에 박는다. 표기 예: `유형: 업무 › 마케팅`.

## 세 가지 유형

### 개인 — 본인 특화 (타인 재사용 어려움)
사용자 개인의 데이터·맥락·톤에 묶여 있어, 남이 그대로 가져다 쓰기 어려운 OS.
- 예: "내 수강생 30명 각자 진도에 맞춘 주간 피드백 초안 생성" (내 명단에 종속)
- 예: "내 노션 DB 구조에 맞춰 회의록 자동 정리" (내 파일 구조에 종속)
- 예: "내 채널 톤·세계관에 맞춘 썸네일 문구 생성" (내 창작 톤에 종속)
- 판별: "이걸 다른 사람에게 주면 바로 쓸 수 있나?" → 아니오면 개인.

### 삶 — 보편 (누구나 사용 가능)
특정인에 종속되지 않아 널리 쓸 수 있는 생활 밀착형 OS.
- 예: 식단 관리, 가계부 정리, 여행 일정 짜기, 운동 루틴 코치, 독서 기록.
- 판별: "낯선 사람도 설명 없이 바로 쓸 수 있나?" → 예면 삶.

### 업무 — 사내·업무 자동화 (세부 카테고리 필수)
직무·비즈니스 업무를 자동화하는 OS. **반드시 한 단계 더 세분화**한다.
- `마케팅` (콘텐츠·광고·SNS·성과분석)
- `디자인` (시안·에셋·브랜드 가이드)
- `개발` (코드리뷰·배포·문서화)
- `기획·PM` (PRD·회의록·로드맵)
- `영업` (리드·제안서·CRM)
- `경영지원` (인사·재무·총무)
- `데이터·분석` (리포트·대시보드)
- `CS·운영` (문의 응대·FAQ)
- (해당 없으면 가장 가까운 것 + 괄호로 실제 직무 병기)

## 제안·확정 규칙
1. Claude가 인터뷰 내용을 근거로 유형 하나를 **먼저 제안**한다 — "이건 '업무 › 마케팅'으로 보이는데, 사내 콘텐츠 성과를 다루니까요. 맞나요?"
2. 사용자가 확인·수정한다.
3. 업무면 세부 카테고리까지 정한다.
4. 확정값을 청사진 헤더 `유형:`과 첫 부품 항목, 그리고 결과물(스킬/플러그인/PRD)에 배지로 표기.
