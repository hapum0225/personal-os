# 자취 직장인의 OS 청사진

- **작성일**: 2026-07-24
- **유형**: 삶 (누구나 사용 가능)
- **OS Core**: 이번 주 컨디션·목표만 정하면, 요일별 식단과 장보기 리스트가 자동으로 나오는 구조.

## 1. 생활 환경 (지금)
혼자 사는 직장인. 시간을 가장 많이 쓰는 활동(집안일 쪽): (1) 끼니 정하기, (2) 장보기, (3) 간단 조리.

## 2. 반복 소모 (반복 비용)
매주 "뭐 먹지"를 새로 고민하고, 장을 봐도 빠뜨려 마트를 두 번 간다. 비용 유형: **결정 비용 + 정리 비용**. 대조 기법으로 "메뉴만 정해지면 장보기는 쉬운데, 그 '정하기'에서 30분이 샌다"가 드러남.

## 3. OS Core (이게 풀리면)
일요일 저녁에 이번 주 컨디션·목표(예: 자취식·가볍게)만 정하면 요일별 식단과 통합 장보기 리스트가 떠서, 고르고 사기만 하면 되는 상태. → 한 문장: *컨디션·목표만 정하면 식단과 장보기 리스트가 나오는 구조.*

## 4. 부품 지도 (도달 경로)
- [x] **주간 식단 + 장보기 생성기** ← **첫 부품 (이번에 만든 것)** *(출력 생성)*
- [ ] 냉장고 재료를 반영해 중복 구매를 막는 것 *(입력 처리)*
- [ ] 남은 재료로 다음 주 메뉴 제안 *(결정 보조)*

가장 비어 있는 묶음: 출력 생성.

## 5. 첫 부품
- **이름**: `weekly-meal-planner`
- **유형**: 삶
- **형태**: A (스킬)
- **결과물**: `weekly-meal-planner/SKILL.md`

## 6. 다음 부품 후보 (다음 인터뷰에서)
- 냉장고 재료 반영(입력 처리) — 이게 되면 중복 구매를 막고 리스트가 더 정확해짐.

## 결정 로그
- OS Core를 '컨디션·목표 → 식단 + 장보기 리스트'로 잡음 — 이유: 병목이 '조리'가 아니라 '정하기'라서.
- 유형을 '삶'으로 봄 — 이유: 특정인에 종속되지 않아 누구나 그대로 쓸 수 있음.
- 첫 부품으로 '식단 + 장보기 생성기'를 고름 — 이유: 매주 30분의 결정 비용을 바로 없앰.
- 형태를 A(스킬)로 정함 — 이유: 조건을 물어 리스트를 생성하는 대화형이라 가장 가볍고 즉시 사용 가능.
- 참고 차용: 참고 없이 처음부터 (식단 규칙이 개인 취향이라 사례보다 직접 문답이 나음).
