# os-blueprint.md 골격 (blueprint-format)

인터뷰가 끝나면 만드는 **OS 청사진** 파일의 골격이다. 이 파일이 블루프린트 골격의 **단일 출처**다. (SKILL.md·템플릿에 이 골격을 다시 인라인하지 않는다.)

산출물 위치: `<output_dir>/os-blueprint.md`.

```markdown
# <사용자 이름 또는 프로젝트>의 OS 청사진

- **작성일**: <YYYY-MM-DD>
- **유형**: <개인 / 삶 / 업무 › 세부카테고리>   ← references/os-types.md 참고
- **OS Core**: <핵심 구조/가치 한 문장. 예: 원고 하나로 모든 SNS 플랫폼에 자동 발행되는 구조>

## 1. 생활 환경 (지금)
<Step 1 요약: 하는 일 + 시간 많이 쓰는 활동 3가지>

## 2. 반복 소모 (반복 비용)
<Step 2 요약 + Phase 1에서 끌어낸 가설. 비용 유형(결정/집중/정리) 표시>

## 3. OS Core (이게 풀리면)
<Step 3 요약: 90% 자동화된 아침의 모습 + 위 OS Core 문장으로 압축된 이유>

## 4. 부품 지도 (도달 경로)
- [ ] <부품 1 — ___을 자동으로 ___해주는 것>
- [x] <부품 2>  ← **첫 부품 (이번에 만든 것)**
- [ ] <부품 3>
<입력 처리 / 결정 보조 / 출력 생성 묶음으로 정리>

## 5. 첫 부품
- **이름**: <부품 이름 (kebab-case slug)>
- **유형**: <개인 / 삶 / 업무 › 세부카테고리>
- **형태**: <A 스킬 / B 플러그인 / C 프로덕트 PRD>
- **결과물**: <산출물 폴더 또는 파일 경로>

## 6. 다음 부품 후보 (다음 인터뷰에서)
<우선순위 두 번째 부품 1~2개 메모>

## 결정 로그
<이번 인터뷰의 주요 선택과 이유를 시간순으로. 예:>
- OS Core를 '___ 하나로 ___ 되는 구조'로 잡음 — 이유: ...
- 첫 부품으로 X를 고름 — 이유: 주당 회수 시간이 가장 큼
- 유형을 '업무 › 마케팅'으로 봄 — 이유: 사내 콘텐츠 업무 자동화라서
- 형태를 A(스킬)로 정함 — 이유: 대화형이라 가장 가볍고 즉시 사용 가능
- 참고 차용: <참고한 사례와 출처, 또는 '참고 없이 처음부터'>
```

## 작성 규칙

- **OS Core**는 Step 3에서 사용자가 잡은 문장(구조형 또는 가치형)을 그대로 박는다.
- **유형** 배지는 Step 5에서 확정한 값(개인/삶/업무›세부)을 헤더와 첫 부품 항목 양쪽에 표기한다.
- 부품 목록의 체크박스는 첫 부품만 `[x]`.
- **결정 로그**는 사용자가 나중에 "내 OS가 왜 이렇게 생겼는지"를 되짚을 수 있도록, 주요 갈림길마다 선택과 이유를 남긴다. 참고 사례를 차용했다면 출처도 남긴다.
- 요약은 사용자 답변 원문 복붙이 아니라 정리된 문장으로.
