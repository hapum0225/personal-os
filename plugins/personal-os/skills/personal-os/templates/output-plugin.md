# 형태 B · Claude Code 플러그인 만들기 (output-plugin)

첫 부품을 **Claude Code 플러그인**으로 만든다. 슬래시 커맨드·훅(특정 이벤트에 자동 실행)·MCP 서버를 묶을 수 있다. 셋 중 가장 무거우니, 글 정리·생성 도우미라면 A(스킬)를 먼저 권한다.

> ⚠️ 여기서 만드는 건 **인터뷰 결과물로서의 플러그인**이다. 이 스킬 자체를 배포하는 `personal-os` 마켓플레이스 플러그인과는 별개다.

## 언제 B인가
터미널 워크플로우, **특정 이벤트에 자동 실행(훅)**, 외부 API 연동(MCP)이 필요할 때.

## Step 6 질문 (Q 톤 — 발판 제공)

1. **한 줄 정체성** — "이 플러그인을 한 문장으로? 예: '세션을 시작하면 오늘 할 일을 자동 브리핑'."
2. **구성 요소** — "무엇이 필요한가요? (복수 선택) ⬚ 슬래시 커맨드 ⬚ 훅(자동 실행) ⬚ 스킬 ⬚ MCP 서버. 예: '세션 시작 훅 + 브리핑 커맨드'."
3. **각 요소의 역할** — 고른 것마다 한 줄. "훅은 언제 터지나요? 커맨드는 뭘 하나요?"
4. **입력** — "사용자가 뭘 넣나요? 인자·환경변수·파일 경로 등."
5. **출력·부수효과** — "무엇을 만들고 무엇을 바꾸나요? (파일 생성/수정, 알림 등)"
6. **외부 의존** — "API 키나 외부 서비스가 필요한가요?"

## 산출물 골격 (단일 출처)

`<output_dir>/<plugin-slug>/`에 **유효한 플러그인 디렉터리**로 만든다. 고른 요소만 생성한다.

```text
<plugin-slug>/
├── .claude-plugin/
│   └── plugin.json          # name(필수), version, description
├── commands/                # 슬래시 커맨드 (고른 경우) — <이름>.md
├── hooks/
│   └── hooks.json           # 훅 (고른 경우) — 공식 구조
└── skills/
    └── <이름>/SKILL.md      # 스킬 (고른 경우)
```

`plugin.json` 최소 형태:
```json
{
  "name": "<plugin-slug>",
  "version": "0.1.0",
  "description": "<한 줄 정체성>"
}
```

## 훅 안전 규칙 (중요)
- 훅은 코드를 자동 실행하므로 **사용자 검토·승인 없이 설치하거나 실행하지 않는다.**
- 훅은 반드시 공식 구조(`hooks/hooks.json`)를 지키고, 실행 커맨드는 `${CLAUDE_PLUGIN_ROOT}` 기준 경로를 쓴다.
- 실행 가능한 스크립트를 만들면 그 내용을 사용자에게 보여주고 무엇을 하는지 설명한 뒤 승인받는다.

## 파일 안전 규칙
A 템플릿과 동일: slug 정규화 / 출력 폴더 밖 금지 / 동명 폴더·파일 `-v2` / Write 불가 시 코드블록 폴백.

## 완료 조건 (검증 통과 후에만 "완료")
1. `claude plugin validate <plugin-slug>`를 실행할 수 있으면 실행해 통과를 확인한다.
2. 실행이 어려우면 `plugin.json`을 다시 읽어 `name`이 kebab-case인지, 고른 요소의 폴더·파일이 실제로 있는지 확인한다.
3. 훅이 있으면 `hooks/hooks.json`이 유효한 JSON이고 커맨드 경로가 `${CLAUDE_PLUGIN_ROOT}` 기준인지 확인한다.
4. 어긋나면 고쳐서 재검증한다.

## 설치 안내
로컬 플러그인은 마켓플레이스 없이도 시험할 수 있다. 다만 설치·활성화는 외부 설정 변경이므로 사용자에게 방법을 안내하고 승인받은 뒤 진행한다. 자세한 배포는 저장소 README의 설치 절차를 참고하라고 안내한다.
